## Decision: build a move inspector, then a route to a selected part

**The interaction:** select a part and one supported direction. Keep the arrow in place, dim the surrounding geometry, and mark the surfaces that block that move. Remove the blocker and retry with the same part and direction. The same evidence explains a step in Guide Forge and changes the player's legal options in Blitz. Keep the control usable on mute and make the direction buttons or handles distinct from orbit dragging.

Blitz already shudders the clicked part, flashes blockers, and has a ghost arrow for legal hints. Existing blocked feedback is computed from the axis with the fewest blockers when no axis is clear; the event drops that axis and the spark is drawn at the clicked part's center. A second flash does not add a capability. The new inspector needs an explicit direction, durable evidence from that direction, and a retry that does not silently choose a different direction.

Use the existing `createStepVerifier` on the current list of live parts in a worker. It yields `fromTriangles` and `toTriangles` for each blocking part. Check the selected path before using it to authorize a move. Blitz's coarse graph alone is inadequate for this claim: solved levels don't get all blockers discovered by stage 3. Display “blocking faces”; the verifier does not return first impact time or a continuous collision guarantee. A direction arrow plus faces is the first version. Keep free dragging, continuous physics, and spin validation out of the hero's promise.

**Product value:** let a Guide Forge user pick the component they need to service and export one checked route to it. A verified prefix of the existing plan is acceptable as a first pass if it is explicitly described as one route. Its length is not a minimum prerequisite count. Put the proof on one screen: target, the blocker, and the result. If actual planner behavior must change to give a useful target route, test that separately before promising it.

**Skeleton Crew proof:** the shared artifact is the move verdict and evidence, not the UI. Document one small example that runs without either app's UI. Both judge links should open quickly; report import failures directly.

## Probes from the current checkout

- **Hero candidate from outside the repo: Innerscene's CC0 two-plate mould.** The unchanged [published GLB](https://www.innerscene.com/tools/library/3d-parts/two-plate-mould-open-0cad1380), SHA-256 `5b327a4eadea3e25c02ae0fe024a16b49cf53826c9eb7e3e766dfd0d40327c05`, solved in 23 steps in both app pipelines. Guide Forge's checker returned zero hits and its exporter produced a 23-step offline HTML manual headlessly, without viewport snapshots. The strongest visual pair is the upper plate moving straight up: its locating ring is the only blocker for the selected translation. The verifier marked 404 triangles on the ring and the separate checker logged 766 hits. The game allows the ring's move, its translation also passed the separate checker, and the identical plate translation returned zero hits with the ring removed. This gives us an external input and a tested causal sequence. Stage the actual camera angle before committing to it. The asset is a third-party visualization model; it does not establish a real service procedure. The engine's shape heuristic applied a screw animation to some slender pins and pillars, so present the hero as a straight translation and review the generated manual's wording before using it.
- **Lockbox, fixed direction.** The same standoff translation along `[0,-1,0]` is blocked by the box body when it is present. The move verifier reports 512 standoff and 5 body witness triangles, and the separate checker reports 770 ray hits. Remove only the body and the exact same query returns no edges and zero hits. This is strong interaction proof on a built-in fixture; preview the camera angle before choosing it for footage.
- **Geometry revision using actual GLBs.** Exported the bundled captive-ring model, then exported an alternate mesh with only the upper retaining knob removed. The same ring move along `[0,1,0]` goes from 1,296 ray hits to zero. The studio pipeline and Blitz solver both return deadlocked for the original and two removals for the revision; the independent checker reports zero for the revised plan. The audit CLI exits 1 when the knob is reintroduced and passes in the reverse comparison. This is original fixture geometry exported and re-imported, not third-party validation. It does not test the browser upload UI or the Crew host.
- **Untouched external assembly.** [Orbiter v2](https://github.com/RawMechatronicsOrg/Orbiter/tree/main/cad/v2/assembly), GLB SHA-256 `8fb4e7d45ce04bd3943e609dbd60ec85b4e76ea2b08dc86d1ffab35c1df123ba`. The CLI parsed the file and reported 173 geometry parts, 235,162 instantiated triangles, 53 removals before getting stuck, and a 120-part cycle. It exceeds the sampling threshold. Two isolated subassemblies also got stuck in both worker pipelines (4/11 removals in the base, 13/20 in elevation). This is a useful boundary case, not proof that the physical equipment is impossible to service or a working end-to-end import demo. Do not bundle this CAD unless its [license](https://github.com/RawMechatronicsOrg/Orbiter/blob/main/cad/LICENSE) and the event rules are satisfied.

## Ship gates

1. **Visible cause and effect:** a novice can tell what blocked the move and predict the retry on mute. Keep the camera and direction fixed for the first demonstration. Capture the UI; the headless probe is not a substitute.
2. **One independently sourced input:** use the checked CC0 mould candidate in both browser apps. Require a working guide export with captured images and another person completing the selected puzzle task. A real maker's service workflow would strengthen the impact evidence further. If another model does not solve, show the limitation; do not substitute a hidden fixture. Keep the ring revision as proof of the mechanics.
3. **Kiro evidence:** show the existing gearbox regression and its spec/verification change. Tie the new move query to the same type of geometric failure instead of counting integrations on screen.
4. **Defer extras:** new campaign levels, custom physics, camera gestures, and a Crew dashboard can wait. Keep the audit comparison as a short supporting beat, with the CLI named unless a real Crew host run is verified.

Related tools already do [automatic exploded views](https://autodesk.com/support/technical/article/caas/sfdcarticles/sfdcarticles/How-to-create-an-exploded-view-drawing-in-Fusion-360.html), [browser assembly documentation](https://explodeview.com/USER-MANUAL.html), [physics-based disassembly planning](https://assembly.csail.mit.edu/), and [CAD checks in CI](https://github.com/sunnyday-technologies/CADCLAW). The defensible pitch is the inspectable path and the two things the same geometry lets a user do.
